# 프람트테크놀로지 개발팀 인턴 — Legacy-to-MSA 품질 검증

## 한눈에 보기

- **기간:** 2026-01~2026-02
- **환경:** Spring Boot·Thymeleaf, `portal`·`permission`·`judgement`·`destination` 4개 서버 모듈
- **과제:** 약 20만 LOC 전략물자 관리 시스템의 레거시→MSA 전환에서 신규 구현이 기존 업무 규칙과 운영 흐름을 빠뜨리지 않았는지 검증
- **역할:** 레거시 동작 역추적, 단위·통합·운영 테스트 설계·수행, 결함 재현·원인 범위화와 개발팀 전달

## 문제 맥락

문서화된 조건 분기와 산출물 기준이 충분하지 않은 상태에서 전환이 진행됐다. 따라서 단순히 신규 화면이 동작하는지 확인하는 수준이 아니라, 기존 `yestrade`의 실제 동작과 관리원의 변경 요구를 함께 비교 기준으로 복원해야 했다. 신청 유형과 신청서 상태마다 분기가 달라, 화면의 버튼·상태 전이·첨부 조건을 세분화하지 않으면 회귀 누락 위험이 컸다.

## 수행한 일

### 1. 레거시 기준을 테스트 명세로 복원

- 기존 시스템을 직접 실행·분석해 조건 분기, 산출물, 데이터 흐름을 확인했다.
- 모든 화면 버튼과 상태별 경로를 기준으로 테스트 항목을 나누고, 신청 시나리오별 기대 결과를 작성했다.
- 1월에는 레거시 분석과 단위 테스트 설계, 2월에는 통합·운영 테스트와 가변 요구 대응에 집중했다.

### 2. 테스트가 막히는 로컬 환경을 먼저 해결

신청서 제출에는 최소 1개 첨부파일이 필수였고, 이미지 업로드 및 정적·동적 다운로드 오류가 반복돼 제출 로직의 로컬 검증이 막혔다. 업로드 경로를 로컬 환경에 맞게 조정해 제출 단위 테스트가 가능하도록 만들고, 운영 전 검증 공백을 줄였다.

### 3. 모듈 간 계약과 결함 위치를 분리

- 통합 테스트에서 모듈 간 데이터 인터페이스와 전체 워크플로우 정합성을 점검했다.
- 오류를 현상만 보고하지 않고 **레거시 대비 차이·재현 절차·발생 모듈·로직/서버 통신 구분**으로 정리해 전달했다.
- 검색 필터 전달 방식이 모듈마다 path/query parameter로 혼재한 문제를 정리했다. 민감 정보가 없다는 전제에서 전달 방식을 통일하는 데 기여했고, 상세에서 목록으로 복귀할 때 검색 조건이 유지되도록 했다.

## 검증 결과

| 항목 | 확인된 결과 |
| --- | --- |
| 테스트 범위 | 1차 기준 전 모듈 합산 약 8,000개 케이스 |
| 단위 테스트 결함 | 2.6일 내 에러 수정 해결률 100% 달성에 기여 |
| 운영 테스트 | 2월 28일 데이터 이관·첨부파일 관련 오류 100% 해결에 기여 |
| 품질 효과 | 제출 로직의 로컬 테스트 공백 해소, 모듈 단위 원인 추적·커뮤니케이션 체계화 |

## 이 경험에서 입증되는 역량

1. **명세가 불완전한 시스템의 분석력:** 코드·기존 동작·요구사항을 교차해 검증 기준을 만든다.
2. **품질을 위한 환경 문제 해결:** 테스트가 불가능한 조건을 그대로 두지 않고, 검증 가능한 로컬 환경부터 복구한다.
3. **MSA 관점의 결함 분류:** 로직·인터페이스·서버 간 통신을 구분해 조치 주체가 바로 판단할 수 있는 형태로 전달한다.
4. **사용자 흐름 중심의 일관성:** 검색 조건 유지처럼 작은 UX 계약도 모듈 간 구현 차이로 깨지지 않게 다룬다.
