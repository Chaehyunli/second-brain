# SKALA Notion → Obsidian daily sync policy

- Source root: Notion `SKALA` page `39d1d84b-f68e-80f3-89b7-e70a6c911bf9`.
- Graph rule: this sync follows `scripts/VAULT_GRAPH_POLICY.md`. Every new learning leaf must include exactly one baseline link to `[[notion/SKALA/index|SKALA 학습 노트]]`; add at most one further link only when there is a direct, specific learning relationship. The SKALA index is the maintained hub and may be appended for newly created notes. Administrative/policy/configuration files may remain independent.
- Scope: recursively discover and sync all descendant pages. Do not follow pages outside this ancestor tree.
- Destination: `notion/SKALA/` in this Vault. Mirror the **actual Notion child-page hierarchy** below SKALA: every non-leaf instructional parent becomes a directory named from its title (remove `[ ]`, keep the date prefix, replace Windows-unsafe characters `\\ / : * ? " < > |` with `-`), and its descendants are stored beneath it. Example: Notion `[7/20] 데이터 분석 개요 및 기초통계 2` → `notion/SKALA/7-20 데이터 분석 개요 및 기초통계 2/`, with `Day2`, `기업 신용평가 모형`, and `데이터 분석 - 회귀 실습` inside. A leaf's asset directory must sit alongside that leaf inside the same parent—not at the SKALA root. Sync **only leaf pages containing learning material**. Determine hierarchy from an actual child-page relationship, not arbitrary `<page>` references inside a page body; a linked reference alone does not make a page non-leaf. User-confirmed learning leaf `[7/14] Git & AI코딩 & 환경구성 — 강의 정리` (`39d1d84b-f68e-8134-9337-f9f71471b3e3`) is always eligible. One eligible page maps to one Markdown note with `notion_page_id`, source URL, title, sync timestamp, and `content_sha256` in frontmatter. The leaf filename uses the normalized Notion title; when a dated ancestor supplies the date, prefix the filename with that date even if the leaf title omits it. Use `notion_page_id` rather than filename as the stable identity.
- User-designated `Padlet` subtree: when a Notion page titled exactly `Padlet` becomes an actual child of SKALA, mirror its real child hierarchy under `notion/SKALA/Padlet/`. Every nonempty leaf below that page is an eligible learning leaf and must be synchronized when first discovered, regardless of the generic parent-title/administrative-content heuristic. Continue to exclude a leaf only when its own title contains `(수정중)`. Do not infer this subtree from a mere inline link or a similar title; verify the real Notion child relationship.
- Skip non-learning administrative/orientation material, including the `[7/14] OT` page and attendance, mobile attendance, security pledge, schedule, campus, meal, operation, allowance, certificate, contact, and attendance-recognition information. SKALA notes contain learning material only.
- Skip any Notion page whose title contains `(수정중)`. It is not synchronized, supplemented, or committed until that marker is removed from its title; then it is reconsidered as a normal new page.
- Preserve the eligible page's meaningful Markdown content and original Notion URL. Do not archive temporary signed image URLs as durable evidence; retain stable text and page references.
- Write a **source-based detailed learning note**, never a URL plus a short outline. Preserve the original topic flow and decisive headings; explain concepts, definitions, formulas, examples, original code/commands and stored execution results where present, their meaning, cautions, and direct parent/sibling links. Do not invent facts or results, and do not compress a multi-section lecture into a few bullets. A genuinely short Notion source may remain concise, but must show its scope through its source link and explicit context.
- Render safety: before validating or committing any changed SKALA Markdown, run `python3 scripts/normalize_skala_markdown.py --path <note>`. It converts Notion XML tables into GitHub/Obsidian Markdown tables, removes stray language labels immediately before fenced blocks, and wraps unfenced HTML examples in an `html` fenced code block. Keep source HTML examples verbatim inside those fences; never leave executable/rendered HTML examples in prose.
- For the daily hook's identity check, recursively scan every Markdown note under `notion/SKALA/` for `notion_page_id`; manually added nested notes are also frozen after their first commit. Run `python3 scripts/validate_skala_sync.py` before writing. A nonzero result stops the sync; notes missing **both** `synced_at` and `content_sha256` are legacy frozen notes and are reported but must not be rewritten automatically. If multiple files have the same `notion_page_id`, use the file with the later first Git upload commit as canonical and ignore older duplicates; never rewrite or delete either automatically. A missing or tied first-upload time is unsafe and stops the sync.
- Extract only the Notion `<content>` region, remove temporary signed-image URLs, normalize whitespace, then calculate `content_sha256` from that source text for every **new automatic** note's provenance. An uploaded eligible leaf is frozen after its first GitHub commit: a later change to that same `notion_page_id` must not update its body, title, filename, hash, timestamp, links, or Git history unless the user explicitly requests it.
- For a **new** eligible page ID, compare its learning purpose and key concepts against the existing SKALA notes before writing. If it is materially identical, do not add a note. If it is closely related but adds distinct learning value, append a short `## 보충 — <새 페이지 제목>` section at the end of the closest existing note, with the new Notion URL; do not alter the existing sections. Do this only once per new source URL. Otherwise create a separate note.
- Safety: stop before writing or committing if `git status --porcelain` reports unrelated local changes. Do not use reset or force push.
- Commit each newly added learning leaf separately and use its exact Notion title: `노션: SKALA - <페이지 제목> 업데이트`. For a supplement, use `노션: SKALA - <새 페이지 제목> 보충`. Never create an automatic update or deletion commit for an already uploaded page itself.
- Push each successful commit to `origin/main`. If no page changed, make no commit and return no user-facing report.
- Public blog derivatives: retain both the canonical SKALA learning note and the `blog/` publication record. Never match merely by similar titles or content. When the Tistory post visibly declares `학습 원본:` or `SKALA 원문:` followed by a Notion URL whose ID matches a local SKALA note, append reciprocal Obsidian links: `## 학습 기준본` in the blog note and `## 공개 게시물` in the SKALA note. This relationship-only append is allowed for an otherwise frozen SKALA note; do not change source provenance fields or original learning sections.
