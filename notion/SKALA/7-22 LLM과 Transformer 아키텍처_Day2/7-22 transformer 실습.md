## 1. 실습 목적과 비교 대상

목적은 Transformer 기반 미니 언어모델의 구조·학습 과정을 이해하고, 주어진 Baseline의 설정 변경이 성능에 어떤 차이를 만드는지 비교하는 것이다. 원문이 제시한 개선 후보는 다음 여섯 가지다.

1. 모델 크기: `n_layer`, `n_head`, `n_embd`
2. 학습 반복 수: `MAX_ITERS`
3. 문맥 길이: `block_size`
4. 생성 파라미터: `temperature`, `top_k`
5. 데이터 양
6. Causal Mask 유무

이 실습에서는 제한된 시간 때문에 **모델 크기**와 **학습 반복 수**만 선택했다. 각 비교에서는 대상 외 조건을 같게 두고 Loss 곡선과 생성 문장으로 차이를 해석했다. 즉 결과를 “설정 하나의 순수한 인과효과”로 과도하게 단정하기보다, 고정한 조건 아래의 실습 관찰로 읽어야 한다.

## 2. 데이터·환경·모델 흐름

### 데이터와 실행 환경

- 데이터: 제공된 김유정 작품 텍스트
- 토큰화: 문자 단위(Character-level) — 등장 문자를 하나의 토큰으로 처리
- 외부 데이터 추가: 없음
- 실행: Python, PyTorch, Google Colab
- 모델: Transformer Decoder 기반 미니 언어모델
- 과업: Next Token Prediction
- 마스크: Causal Mask 적용

### 입력에서 다음 문자 확률까지

```plain text
입력 텍스트
→ 문자 단위 토큰화
→ Token Embedding
→ Position Embedding
→ Masked Self-Attention
→ Feed Forward Network
→ Linear Layer
→ 다음 문자 확률 예측
```

문자 단위 토큰화는 구현이 단순하고 사전에 없는 단어도 처리할 수 있다. 예를 들어 `오늘도`는 `오 / 늘 / 도`처럼 분리된다. 반면 단어의 의미를 직접 표현하지 못하고, 긴 문맥을 학습하려면 더 많은 토큰이 필요하다.

각 문자 ID는 `n_embd` 차원의 벡터가 된다. Token Embedding은 문자 자체의 표현이고, Position Embedding은 순서 정보를 준다. Transformer는 입력 순서를 자동으로 알지 못하므로 위치 정보가 필요하다.

Self-Attention에서는 토큰을 Query·Key·Value로 바꾸고 Query와 Key의 유사도로 Attention Score를 계산한 뒤 Value를 가중합한다. 이 모델은 자기회귀(next-token) 생성이므로 미래 토큰을 참고하면 안 된다. Causal Mask는 이를 막는다.

```plain text
첫 번째 토큰 → 첫 번째 토큰만 참고
두 번째 토큰 → 첫 번째, 두 번째 토큰 참고
세 번째 토큰 → 첫 번째, 두 번째, 세 번째 토큰 참고
```

| 항목 | 설정 |
| --- | --- |
| Tokenizer | Character-level |
| `block_size` | 128 |
| 데이터셋 | 동일한 김유정 작품 텍스트 |
| Causal Mask | 적용 |
| 생성 길이 | 동일 |

생성문을 비교할 때 시작 프롬프트·생성 길이·생성 파라미터를 통제한 이유는 모델 설정 외 요인의 영향을 줄이기 위해서다.

## 4. 실험 1 — 모델 크기 변경

### 변경한 파라미터

모델 크기는 Transformer block 수 `n_layer`, Multi-Head Attention head 수 `n_head`, embedding 차원 `n_embd`로 바꿨다. 세 모델 모두 `block_size = 128`, `MAX_ITERS = 100`으로 유지했다.

| 모델 | `block_size` | `n_layer` | `n_head` | `n_embd` |
| --- | ---: | ---: | ---: | ---: |
| Small | 128 | 3 | 3 | 96 |
| Baseline | 128 | 6 | 6 | 192 |
| Large | 128 | 12 | 12 | 384 |

원문의 예상은 Small보다 Baseline·Large가 문자 관계와 문맥 패턴을 더 복잡하게 학습하되, 모델이 클수록 학습 시간·메모리 사용량도 늘고, 데이터나 학습 횟수가 부족하면 Large의 이점이 작아질 수 있다는 것이었다.

### 저장된 실행 결과

| 모델 | 최종 Loss | 학습 시간 |
| --- | ---: | ---: |
| Small | 4.00911 | 3.8초 |
| Baseline | 3.68497 | 17.4초 |
| Large | 3.65684 | 52.2초 |

원문은 학습 전 생성이 무작위 한글 문자열에 가까웠고, 학습 뒤 세 모델 모두 한국어 문장 형태를 생성했다고 기록한다. 동일 시작 프롬프트는 `오늘도 또 우리 수탉이 막`이었다. Baseline·Large는 김유정 작품과 비슷한 문체·대화 형식을 일부 만들었지만, Small은 단어·문장 반복과 문맥의 불안정성이 더 컸다.

실험 결과 해석은 다음과 같다.

- 크기가 커질수록 최종 Loss는 `4.00911 → 3.68497 → 3.65684`로 낮아졌다.
- 그러나 Large의 Loss 개선 폭은 Baseline 대비 작았고, 생성 문장의 자연스러움도 큰 차이가 아니었다.
- 학습 시간은 `3.8초 → 17.4초 → 52.2초`로 크게 증가했다.
- 원문은 데이터가 김유정 작품 8편, 약 **97K 문자** 수준이라 큰 모델이 데이터를 일반화하기보다 기억하는 방향으로 갈 가능성을 제시한다. 따라서 낮은 학습 Loss만으로 생성 품질 개선을 단정할 수 없다.

## 5. 실험 2 — 학습 반복 수 변경

이번에는 모델 구조를 Baseline으로 고정하고 `MAX_ITERS`만 바꿨다.

```plain text
block_size = 128
n_layer = 6
n_head = 6
n_embd = 192
```

| 구분 | `MAX_ITERS` | `block_size` | `n_layer` | `n_head` | `n_embd` |
| --- | ---: | ---: | ---: | ---: | ---: |
| Short | 100 | 128 | 6 | 6 | 192 |
| Baseline | 500 | 128 | 6 | 6 | 192 |
| Long | 2000 | 128 | 6 | 6 | 192 |

원문은 100회에서는 학습 부족으로 Loss가 높고, 500회에서는 기본 문자·문맥 패턴을 학습하며, 2000회에서는 더 낮은 Loss가 나올 수 있으나 과도한 학습은 과적합을 낳을 수 있다고 예상했다.

### 저장된 실행 결과: Train/Validation Loss

| `MAX_ITERS` | Train Loss | Validation Loss |
| --- | ---: | ---: |
| 100 | 3.59 | 3.89 |
| 500 | 3.52 | 3.72 |
| 2000 | 3.70 | 3.94 |

원문에는 100·500·2000 iteration의 생성문도 보관되어 있다. 100회 결과는 문장 형태가 일부 나타나도 반복과 연결 단절이 컸고, 500회 결과는 더 긴 한국어 문장 구조와 대화 형식을 보였다. 2000회 결과 역시 문장 형태가 나타났지만, 원문은 긴 반복 학습이 항상 생성 품질을 개선하지 않으며 작은 데이터셋에서는 암기 위험이 있다고 해석한다.

여기서 표의 수치를 보면 500회가 세 값 중 Train/Validation Loss 모두 가장 낮다. 따라서 “반복 수가 늘수록 Loss가 계속 감소한다”는 서술은 이 저장 표의 `2000` 결과(`3.70`, `3.94`)와 일치하지 않는다. 노트에서는 임의로 한쪽을 고치지 않고, **원문 서술과 표 사이에 확인이 필요한 차이가 있다**고 보존한다.

## 6. 모델 크기와 반복 수를 함께 해석하기

| 개선 요소 | 바꾼 내용 | 기대 효과 | 비용·한계 |
| --- | --- | --- | --- |
| 모델 크기 | `n_layer`, `n_head`, `n_embd` 증가 | 표현력 증가 | 학습 시간·메모리 증가 |
| 학습 반복 수 | `MAX_ITERS` 증가 | 파라미터 최적화 진행 | 학습 시간·과적합 가능성 증가 |

모델 크기를 키우는 일은 모델이 표현할 수 있는 용량을 늘리는 일이고, 반복 수를 늘리는 일은 동일한 모델이 데이터를 더 오래 보게 하는 일이다. 큰 모델도 학습이 부족하면 성능이 충분하지 않을 수 있고, 작은 모델도 오래 학습해 표현력 한계를 넘지는 못한다. 그래서 원문은 모델 크기, 반복 수, 데이터 양, 학습 시간, GPU 메모리, validation loss, 생성 품질을 함께 판단해야 한다고 결론짓는다.

## 7. Loss와 생성 품질은 같은 지표가 아니다

Loss는 실제 다음 토큰에 모델이 얼마나 높은 확률을 주었는지를 나타낸다. 일반적으로 Loss 감소는 next-token 예측 개선 신호지만, 사람이 읽기에 자연스러운 문장을 보장하지는 않는다. 원문은 다음 요소가 생성문에도 영향을 준다고 열거한다.

- 데이터의 품질·양
- 모델 크기와 학습 반복 수
- 시작 프롬프트
- `temperature`, `top_k`
- 생성 길이와 무작위 sampling

따라서 관찰 기준을 Loss 하나로 한정하지 않고 한글 생성 여부, 띄어쓰기·문장부호, 반복, 문장 구조 유지, 특정 표현의 과도한 반복, 원문 작품과 비슷한 문체의 출현을 같이 봤다.

## 8. 한계와 다음 실험

원문이 명시한 한계는 다음과 같다.

1. 시간 제약으로 `block_size`, `temperature`, `top_k`, 데이터 양, Causal Mask 유무는 직접 비교하지 못했다.
2. 데이터셋이 작아 큰 모델의 일반화 성능을 충분히 판단하기 어렵고 암기 가능성이 있다.
3. Character-level tokenizer는 단순하지만 단어 의미를 직접 표현하지 못한다.
4. 모델 크기 비교에서 `n_layer`, `n_head`, `n_embd`를 동시에 바꿔 각각의 독립 효과를 분리하기 어렵다.
5. Train Loss만으로는 과적합을 판단하기 어려우므로 Train/Validation Loss를 함께 볼 필요가 있다.

후속 실험으로는 `block_size` 증가에 따른 긴 문맥 활용과 Attention 비용, `temperature`·`top_k` 조절의 안정성/다양성 변화, 데이터 양 증가, Causal Mask 제거가 만드는 부정한 낮은 Loss, BPE·SentencePiece 같은 subword tokenizer 적용을 제안한다. 특히 Causal Mask를 제거해 Loss가 낮아져도 미래 정답을 미리 보는 것이므로 정상적인 next-token 생성 성능 향상으로 해석하면 안 된다.

## 결론

이 실습은 모델 크기와 학습 반복 수가 모두 Transformer 미니 언어모델의 성능에 영향을 주지만, 어느 하나만 늘리는 것으로 충분하지 않음을 보여준다. 모델 크기는 표현력을 늘리지만 시간·메모리 비용을 키우며, 반복 수는 최적화를 진행하지만 작은 데이터에서는 과적합 위험을 키운다. 따라서 데이터 양·모델 용량·학습 횟수의 균형, 그리고 Loss와 실제 생성 결과의 병행 검토가 핵심이다.
