## 요구사항과 ERD

관리 대상은 `department`, `professor`, `student`, `course`, `enrollment`다.

- 학생과 교수는 하나의 학과에 소속된다.
- 과목은 하나의 학과가 개설하고, 담당 교수는 미정일 수 있다.
- 학생과 과목은 N:M 관계다. `enrollment`가 교차 테이블로 이를 해소한다.
- 같은 학생이 같은 과목을 중복 신청하지 못하도록 `(student_id, course_id)`에 `UNIQUE`를 둔다.
- 성적은 수강신청 시점에 NULL일 수 있다.

| 관계 | 부모(1) | 자식(N) | 삭제 동작 |
| --- | --- | --- | --- |
| 학과–교수 | `department` | `professor` | `RESTRICT` |
| 학과–학생 | `department` | `student` | `RESTRICT` |
| 학과–과목 | `department` | `course` | `RESTRICT` |
| 교수–과목 | `professor` | `course` | `SET NULL` |
| 학생–수강신청 | `student` | `enrollment` | `CASCADE` |
| 과목–수강신청 | `course` | `enrollment` | `CASCADE` |

설계의 핵심은 **삭제 규칙이 도메인 의미를 표현한다**는 점이다. 학과를 지우기 전에 소속 데이터부터 정리하게 하려면 `RESTRICT`, 담당 교수가 사라져도 과목은 남겨야 하면 `SET NULL`, 학생/과목이 사라지면 수강 기록도 더 이상 유효하지 않다면 `CASCADE`를 사용한다.

## DDL: 제약조건이 포함된 테이블 생성

원문은 하나의 트랜잭션 안에서 테이블을 만들고, 단계별 `SAVEPOINT`를 둔다. 아래는 동일한 구조를 학습용으로 정리한 코드다.

```sql
BEGIN;

CREATE TABLE IF NOT EXISTS department (
  dept_id      SERIAL PRIMARY KEY,
  dept_name    VARCHAR(50) NOT NULL UNIQUE,
  office_phone VARCHAR(20),
  created_at   TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE IF NOT EXISTS professor (
  prof_id    SERIAL PRIMARY KEY,
  prof_name  VARCHAR(30) NOT NULL,
  dept_id    INT NOT NULL,
  hire_date  DATE NOT NULL DEFAULT CURRENT_DATE,
  email      VARCHAR(100) UNIQUE,
  CONSTRAINT fk_prof_dept FOREIGN KEY (dept_id)
    REFERENCES department (dept_id) ON DELETE RESTRICT
);

CREATE TABLE IF NOT EXISTS student (
  student_id   SERIAL PRIMARY KEY,
  student_name VARCHAR(30) NOT NULL,
  dept_id      INT NOT NULL,
  grade        SMALLINT NOT NULL DEFAULT 1,
  gender       CHAR(1),
  birth_date   DATE,
  enroll_date  DATE NOT NULL DEFAULT CURRENT_DATE,
  email        VARCHAR(100) UNIQUE,
  CONSTRAINT fk_stu_dept FOREIGN KEY (dept_id)
    REFERENCES department (dept_id) ON DELETE RESTRICT,
  CONSTRAINT chk_grade CHECK (grade BETWEEN 1 AND 4),
  CONSTRAINT chk_gender CHECK (gender IN ('M', 'F'))
);

CREATE TABLE IF NOT EXISTS course (
  course_id   SERIAL PRIMARY KEY,
  course_name VARCHAR(50) NOT NULL,
  dept_id     INT NOT NULL,
  prof_id     INT,
  credit      SMALLINT NOT NULL DEFAULT 3,
  semester    VARCHAR(10) NOT NULL,
  capacity    INT NOT NULL DEFAULT 40,
  CONSTRAINT fk_course_dept FOREIGN KEY (dept_id)
    REFERENCES department (dept_id) ON DELETE RESTRICT,
  CONSTRAINT fk_course_prof FOREIGN KEY (prof_id)
    REFERENCES professor (prof_id) ON DELETE SET NULL,
  CONSTRAINT chk_credit CHECK (credit BETWEEN 1 AND 6),
  CONSTRAINT chk_capacity CHECK (capacity > 0)
);

CREATE TABLE IF NOT EXISTS enrollment (
  enroll_id    SERIAL PRIMARY KEY,
  student_id   INT NOT NULL,
  course_id    INT NOT NULL,
  enroll_date  DATE NOT NULL DEFAULT CURRENT_DATE,
  grade_score  NUMERIC(4,1),
  grade_letter VARCHAR(2),
  CONSTRAINT fk_enroll_student FOREIGN KEY (student_id)
    REFERENCES student (student_id) ON DELETE CASCADE,
  CONSTRAINT fk_enroll_course FOREIGN KEY (course_id)
    REFERENCES course (course_id) ON DELETE CASCADE,
  CONSTRAINT uq_enroll UNIQUE (student_id, course_id),
  CONSTRAINT chk_score CHECK (grade_score BETWEEN 0 AND 100)
);

COMMIT;
```

### DDL에서 확인할 항목

| 요소 | 실습에서의 역할 |
| --- | --- |
| `SERIAL PRIMARY KEY` | 레코드 식별자 자동 생성 |
| `NOT NULL` | 필수 입력값 보장 |
| `UNIQUE` | 학과명·이메일·동일 수강의 중복 방지 |
| `CHECK` | 학년, 성별, 학점, 정원, 점수의 범위 제한 |
| FK | 학과·교수·학생·과목 관계 유지 |
| `DEFAULT` | 입력하지 않은 생성일·학년·정원을 합리적 기본값으로 처리 |

`CHECK (grade_score BETWEEN 0 AND 100)`은 NULL을 자동으로 거부하지 않는다. 성적 미입력을 허용하려면 현재 설계처럼 NULL 허용 상태를 유지하고, `NOT NULL`을 추가하지 않는다.

## 초기 데이터 입력(DML)

원문은 학과·교수·학생·과목·수강신청 데이터를 최소 10건 이상 넣고, 각 삽입 후 `SAVEPOINT`를 둔다. 재실행 가능성을 위해 `ON CONFLICT`를 사용한다.

```sql
-- 중복되지 않는 자연키/고유키가 있을 때 재실행 안전성을 확보한다.
INSERT INTO department (dept_name, office_phone)
VALUES ('컴퓨터공학과', '02-300-1001')
ON CONFLICT (dept_name) DO NOTHING;

-- 수강신청은 같은 학생-과목 조합을 중복 등록하지 않는다.
INSERT INTO enrollment (student_id, course_id, enroll_date, grade_score, grade_letter)
VALUES (1, 1, '2024-03-05', 92.5, 'A')
ON CONFLICT (student_id, course_id) DO NOTHING;
```

주의할 점은 `ON CONFLICT DO NOTHING`이 단순히 오류를 숨기는 장치가 아니라는 것이다. 어떤 충돌을 허용할지 고유 제약조건으로 명시되어 있어야 하며, 잘못된 데이터가 “조용히 누락”되지 않도록 삽입 결과를 검증해야 한다.

## 기초 조회: SELECT, WHERE, ORDER BY

원문은 다음 조건 패턴을 실습한다.

```sql
-- 전체 학과를 이름순으로 조회
SELECT dept_id, dept_name, office_phone
FROM department
ORDER BY dept_name ASC;

-- 3학년 학생만, 학번순으로 조회
SELECT student_id, student_name, grade, gender
FROM student
WHERE grade = 3
ORDER BY student_id ASC;

-- 정원 40명 이상 과목, 정원 내림차순
SELECT course_name, credit, capacity
FROM course
WHERE capacity >= 40
ORDER BY capacity DESC;

-- 이름이 김으로 시작하는 학생
SELECT student_id, student_name, dept_id
FROM student
WHERE student_name LIKE '김%'
ORDER BY student_name ASC;

-- 점수 80~100인 수강 기록
SELECT enroll_id, student_id, course_id, grade_score
FROM enrollment
WHERE grade_score BETWEEN 80 AND 100
ORDER BY grade_score DESC;
```

| 패턴 | 예 | 유의점 |
| --- | --- | --- |
| 비교 | `grade = 3`, `capacity >= 40` | 데이터 타입과 NULL 처리 확인 |
| 범위 | `BETWEEN 80 AND 100` | 양 끝값을 포함 |
| 목록 | `dept_id IN (1, 2, 3)` | 복수 선택을 간결하게 표현 |
| 문자열 | `LIKE '김%'` | 앞에 `%`가 붙으면 인덱스 활용이 어려울 수 있음 |
| NULL | `grade_score IS NULL` | `= NULL`이 아니라 `IS NULL` 사용 |
| 정렬 | `ORDER BY grade DESC, student_name ASC` | 앞 기준이 우선, 동률에 다음 기준 적용 |
| 상위 N | `ORDER BY ... LIMIT 5` | 정렬 없이는 “상위” 의미가 불명확 |

## NULL 처리: COALESCE

`COALESCE`는 왼쪽부터 첫 번째 비NULL 값을 반환한다. 실습에서는 미입력 성적·등급·연락처를 표현 가능한 값으로 바꾼다.

```sql
-- 미입력 점수를 0으로 보이게 한다.
SELECT enroll_id, student_id, course_id,
       COALESCE(grade_score, 0) AS score_view
FROM enrollment
ORDER BY enroll_id ASC;

-- NULL 등급을 미평가로 표현한다.
SELECT enroll_id, student_id, course_id,
       COALESCE(grade_letter, '미평가') AS letter_view
FROM enrollment
ORDER BY enroll_id ASC;
```

표시용 `COALESCE`와 실제 값을 0점으로 갱신하는 것은 다르다. 미평가(NULL)를 0점이라는 실제 데이터로 바꾸면 이후 평가 상태를 구분할 수 없으므로, 조회 단계의 표시 변환인지 업데이트인지 구별해야 한다.

## 조건 분기: CASE WHEN

```sql
-- 점수를 등급으로 계산한다.
SELECT enroll_id, student_id, grade_score,
       CASE
         WHEN grade_score IS NULL THEN '미평가'
         WHEN grade_score >= 90 THEN 'A'
         WHEN grade_score >= 80 THEN 'B'
         WHEN grade_score >= 70 THEN 'C'
         WHEN grade_score >= 60 THEN 'D'
         ELSE 'F'
       END AS calc_grade
FROM enrollment
ORDER BY grade_score DESC NULLS LAST;

-- 점수를 합격·불합격으로 분류한다.
SELECT enroll_id, student_id, grade_score,
       CASE
         WHEN grade_score IS NULL THEN '미응시'
         WHEN grade_score >= 60 THEN '합격'
         ELSE '불합격'
       END AS pass_status
FROM enrollment
ORDER BY enroll_id ASC;
```

조건은 위에서 아래로 처음 참인 항목이 선택된다. 그러므로 `>= 90`을 `>= 80`보다 먼저 둬야 하고, NULL은 비교 연산이 아닌 별도 조건으로 먼저 다룬다. `NULLS LAST`는 PostgreSQL에서 NULL 행을 정렬의 마지막에 배치한다.

## 날짜 함수

```sql
-- 생년월일에서 나이를 계산한다.
SELECT student_id, student_name, birth_date,
       EXTRACT(YEAR FROM AGE(birth_date)) AS age
FROM student
ORDER BY age DESC;

-- 입학일 이후의 경과 일수
SELECT student_id, student_name, enroll_date,
       CURRENT_DATE - enroll_date AS days_enrolled
FROM student
ORDER BY days_enrolled DESC;

-- 표시 형식을 바꾼다.
SELECT student_id, student_name,
       TO_CHAR(enroll_date, 'YYYY년 MM월 DD일') AS enroll_fmt
FROM student
ORDER BY student_id ASC;
```

- `CURRENT_DATE`는 날짜만 필요할 때 사용한다.
- `NOW()`는 시간대가 포함된 현재 시점을 다룰 때 유용하다.
- 날짜 뺄셈 결과의 단위와, `AGE()`가 달·일 단위 차이를 포함한다는 특성을 상황에 맞게 확인한다.

1. DBeaver에서 PostgreSQL 17 연결이 정상인지 확인한다.
2. FK 참조 순서대로 `department → professor/student → course → enrollment`를 생성·삽입한다.
3. `\d enrollment` 또는 GUI 스키마 화면에서 PK·FK·UNIQUE·CHECK가 실제로 만들어졌는지 확인한다.
4. 같은 `(student_id, course_id)`를 두 번 넣어 `UNIQUE`가 동작하는지 확인한다.
5. 존재하지 않는 `dept_id`를 가진 학생을 넣어 FK가 막는지 확인한다.
6. 점수 NULL 행에서 `COALESCE`와 `CASE` 결과가 원본 NULL을 변경하지 않는지 조회로 확인한다.
7. `EXPLAIN`을 사용해 조건·정렬이 커졌을 때 인덱스가 필요한지 점검한다.
