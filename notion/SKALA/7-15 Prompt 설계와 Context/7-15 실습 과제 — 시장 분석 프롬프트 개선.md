# [7/15] 실습 과제 — 시장 분석 프롬프트 개선

## 원문
[Notion 원문](https://app.notion.com/p/39e1d84bf68e803c921edf09bfd8fc06)

## 과제 목표
이 실습은 “국내 육아용품 시장 분석해줘”라는 짧은 질문이 왜 경영진 의사결정용 보고서가 되지 못하는지 진단하고, **역할·분석 범위·근거·산출 형식·반론 절차**를 프롬프트에 넣어 결과를 개선한 사례다.

```text
1단계 Baseline → 2단계 한계 진단 → 3단계 Context·Framework 설계 → 4단계 결과 비교
```

## 1. Baseline의 문제: 정보량과 의사결정 품질은 다르다
초기 응답은 출생아 수, 시장 규모, 프리미엄 소비, 채널, 경쟁사, 리스크를 폭넓게 나열했다. 그러나 유아동복·온라인 거래·교육·문화가 포함된 키즈산업 수치를 같은 ‘육아용품 시장 규모’처럼 병치했고, 목표 고객·비교 기준·실행 KPI가 빠져 있었다.

| 과업 요구 | Baseline 상태 | 개선 필요 |
| --- | --- | --- |
| 시장 규모 | 서로 다른 범주의 수치 나열 | 분석 범위와 같은 지표만 사용, 불일치 수치는 참고로 분리 |
| 경쟁사 비교 | 기업명·특징 나열 | 제품·타깃·가격대·채널·차별점의 같은 열로 비교 |
| 목표 고객 | 텐포켓 같은 현상 언급 | 구매 상황·결정권자·불안·지불요인을 정의 |
| SWOT | 리스크 서술 | 분석 주체의 내부 강점·약점과 외부 기회·위협 분리 |
| 진입 전략 | 프리미엄·리세일 방향만 제시 | 제품·채널·가격 검증·KPI·중단 기준을 포함 |

## 2. 2단계 진단 기준
### 검증 가능성
수치에는 기관·발표일·URL·적용 범위·표 번호가 필요하다. 단일 유통사 행사나 특정 플랫폼 지표를 국내 시장 전체 추세로 일반화하지 않는다. 사실·해석·가설·추가 확인 필요를 같은 문체로 섞지 않는다.

### 문서 구조
보고서는 `핵심 결론 → 근거 데이터 → 해석 → 사업적 시사점 → 추가 검증` 순서로 설계한다. 긴 문단과 반복 수치는 표로 통합하고, 배경 설명보다 고객·경쟁·전략에 충분한 비중을 둔다.

### 모호한 표현을 질문으로 바꾸기
- ‘육아용품 시장’ → 어떤 연령·제품군·채널을 포함하는가?
- ‘프리미엄이 승부처’ → 어느 고객이 안전성·소재·A/S·디자인 중 무엇에 얼마를 더 지불하는가?
- ‘리세일 잔존가치’ → 어떤 내구재에서 보증·정품 인증·중고 연계가 가능한가?

## 3. Context Engineering 설계
가상 회사 **루미베베**를 두고, 서울·경기 백화점에서 유모차·카시트·하이체어·아기띠 중심의 6개월 팝업을 검토한다는 조건을 입력했다. 기저귀·분유·유아동복·온라인 전체 거래액은 분석 범위에서 명시적으로 제외했다.

핵심 프롬프트 구성은 다음과 같다.
1. **Role**: 백화점 프리미엄 소비재·영유아 내구재 담당 수석 전략 컨설턴트.
2. **Context**: 회사의 보유 역량·부족 역량·예산·파일럿 조건·우선 고객 가설.
3. **Constraints**: 범위 불일치 수치 금지, 출처 없는 수치 금지, 사실·해석·가설 분리.
4. **Output format**: 시장성·경쟁·고객·SWOT·전략·KPI·Pre-mortem·Sources를 표 구조까지 지정.
5. **Few-shot**: `[확인된 사실] → [해석] → [한계] → [의사결정]` 표기 예시 제공.
6. **Step-back**: 전략 전 시장 정의·백화점 구매 가치·진입 판단 기준을 먼저 검토.
7. **Pre-mortem**: 6개월 뒤 실패를 가정하고 조기 경보·사전 검증·대응을 강제.

## 4. 최종 결과에서 달라진 판단 방식
최종 결론은 전면 입점이 아니라 **조건부 6개월 팝업 파일럿 권고**다. ‘백화점 프리미엄 육아 내구재’의 직접 시장 규모는 공개 자료만으로 확정하기 어렵다고 명시하고, 출생 반등·유통사 행사 확대·프리미엄 카테고리 신호는 방향성 프록시로만 사용했다.

경쟁사(부가부·스토케·싸이벡스)는 대표 제품·타깃·가격대·백화점 접점·차별점·추가 확인 필요 항목을 같은 기준으로 비교했다. 목표 고객은 단순한 소득·연령이 아니라 **첫 아이·안전 불안·추천 의존·실물 체험 필요**라는 구매 상황으로 정의했다.

### 전략 비교
| 전략 | 핵심 | 파일럿 검증 지표 |
| --- | --- | --- |
| A. 신뢰형 트래블 시스템 | 체험·A/S·안전정보와 제품을 결합 | 체험→구매 전환, 객단가, 재고회전, 추천 |
| B. 안전정보·상담 큐레이션 | 소수 SKU와 1:1 상담·체험 중심 | 상담 예약·상담→구매, NPS, 번들 채택 |

두 전략의 공통 선행 조건은 안전 인증이며, 3개월 시점 전환율·재고회전 기준으로 SKU·가격을 수정하고 5개월 시점 손익 기준 미달이면 중단하는 룰을 둔다.

## 5. 프롬프트 기법별 효과
| 기법 | 해결한 문제 |
| --- | --- |
| Role + Context | 분석 주체가 없어 SWOT·전략을 만들 수 없던 문제 |
| Scope + Negative constraints | 서로 다른 시장 범위를 뒤섞는 문제 |
| Grounding + Few-shot | 출처·사실·해석이 섞이는 문제 |
| Output format | 긴 문단·정보 위계 부재 |
| Step-back | 정의 없이 결론부터 내리는 문제 |
| Pre-mortem | 리스크 나열만 하고 대응이 없는 문제 |

**핵심 교훈:** 품질은 정보를 많이 넣어서가 아니라, 모델이 따라야 할 **제약·근거·판단 절차**를 명시해서 높아진다.
