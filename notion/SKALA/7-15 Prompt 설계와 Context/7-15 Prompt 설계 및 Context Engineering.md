- **슬라이드 35** — Sampling control API 예시. **실제 API 키는 코드·문서에 넣지 않고 환경 변수로 관리**한다.
```python
from openai import OpenAI

client = OpenAI(api_key="YOUR_API_KEY")  # 실제 값은 환경 변수에서 주입
response = client.chat.completions.create(
    model="gpt-5.1-mini",
    temperature=0.8, # 무작위성 정도
    top_p=1.0, # 상위 1개의 후보만
    messages=[
        {"role": "system", "content": "너는 친절한 한국의 AI 비서야."},
        {"role": "user", "content": "아이디어 5개만 뽑아줘."},
    ],
)
```
`temperature`와 `top_p`는 다음 토큰 후보 선택의 다양성에 관여한다. 코드는 단순 예시이며, 사용 중인 SDK·모델의 최신 문서를 먼저 확인한다.
- **슬라이드 36** — `max tokens`/출력 길이는 품질을 자동으로 요약하는 옵션이 아니라 생성 가능한 토큰 상한이다. 길이가 길수록 비용·대기 시간이 늘어난다. <br>→ 대답할 때 이 글자 수 넘어가면 무조건 강제로 말을 끊어버려! 라고 내리는 **단호한 가위질 명령**
- **슬라이드 37** — 가장 확률이 높은 토큰이 항상 선택되는 것은 아니다. sampling은 후보 분포에서 추출하므로 같은 입력도 달라질 수 있다.
> 원문 시각 자료()는 만료형 Notion 첨부 URL이므로 원문 페이지에서 확인한다.
- **슬라이드 38** — Temperature는 무작위성 정도를 제어한다. 낮을수록 사실·정형 작업에, 높을수록 발상·다양한 초안에 적합하다. 강의의 예시는 사실형 0.2~0.4, 창의형 1.6~1.8이나 실제 가능한 범위는 모델별로 다르다.<br>→ Temperature 가 높을 수록, 등장할 확률이 적은 창의적인 대답이 선택될 “확률”이 높음<br>→ Temperature 가 낮을 수록, 등장할 확률이 높은 사실적인 대답이 선택될 “확률”이 높음

## 실무 체크리스트
1. **과업을 먼저 분해한다.** 생성·검색·요약·추론 중 무엇인지 구분한다.
2. **RICE/LEGO로 구조화한다.** Role, Instruction, Context, Example과 policy/style/constraints/format을 필요한 만큼 사용한다.
3. **근거와 불확실성을 분리한다.** 최신·내부 정보는 RAG·문서·도구 결과로 보강하고, 근거 없는 확정 표현을 금지한다.
4. **출력 설정을 과업에 맞춘다.** 사실형 작업은 일관성·검증을, 발상형 작업은 다양성·후보 비교를 우선한다.
5. **에이전트에는 Harness를 둔다.** 도구 권한·실패 처리·로그·리뷰 기준·재발 방지를 코드와 문서로 강제한다.
