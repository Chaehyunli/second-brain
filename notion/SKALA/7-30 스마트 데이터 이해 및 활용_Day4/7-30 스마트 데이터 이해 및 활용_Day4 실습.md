## 1. 고객 등급 할인율 UDF

등급 입력의 공백·대소문자를 정규화한 뒤 할인율을 반환한다. `IMMUTABLE`, `STRICT`, `PARALLEL SAFE` 선언은 입력만으로 결과가 정해지고 NULL 처리·병렬 실행 조건을 명시하는 계약이다.

```sql
CREATE OR REPLACE FUNCTION proc_lab.fn_grade_discount_rate(p_grade text)
RETURNS numeric
LANGUAGE sql
IMMUTABLE
STRICT
PARALLEL SAFE
AS $function$
    SELECT CASE upper(trim(p_grade))
               WHEN 'VIP'    THEN 0.15
               WHEN 'GOLD'   THEN 0.10
               WHEN 'SILVER' THEN 0.05
               ELSE 0
           END;
$function$;

SELECT proc_lab.fn_grade_discount_rate(' gold ');
```

```plain text
fn_grade_discount_rate
----------------------
                  0.10
```

`customers`에 적용한 원문 결과에서는 GOLD=0.10, VIP=0.15, SILVER=0.05, BASIC=0으로 계산됐다. 행마다 호출해도 데이터 변경 없이 계산만 수행하는 함수의 예다.

## 2. 기준 재고 미만 상품을 반환하는 함수

`RETURNS TABLE`은 여러 행·열을 조회 결과처럼 돌려줄 때 사용한다. `STABLE`은 동일 쿼리 안에서는 결과가 안정적이라는 전제이고, `STRICT`는 NULL 인자일 때 본문을 실행하지 않는다.

```sql
CREATE OR REPLACE FUNCTION proc_lab.fn_products_below_stock(p_threshold integer)
RETURNS TABLE (
    product_id bigint, product_name varchar, stock_qty integer,
    shortage_qty integer, unit_price numeric
)
LANGUAGE sql STABLE STRICT
AS $function$
    SELECT p.product_id, p.product_name, p.stock_qty,
           p_threshold - p.stock_qty AS shortage_qty, p.unit_price
    FROM proc_lab.products AS p
    WHERE p.active = true AND p.stock_qty < p_threshold
    ORDER BY p.stock_qty, p.product_id;
$function$;

SELECT * FROM proc_lab.fn_products_below_stock(70);
```

```plain text
product_id|product_name|stock_qty|shortage_qty|unit_price
----------+------------+---------+------------+----------
         3|27인치 모니터  |       40|          30| 329000.00
         5|웹캠         |       60|          10|  79000.00
```

임계값은 함수 인자로 받고 부족 수량은 `p_threshold - stock_qty`로 계산하므로, 같은 SQL을 여러 임계값에 재사용할 수 있다.

## 3. 고객 주문 요약 JSONB 함수

이 함수는 고객 정보를 조회하고 취소 주문을 제외한 주문 수·총액을 `jsonb_build_object`로 만든다. 고객이 없으면 `INTO STRICT`의 `NO_DATA_FOUND`를 잡아 `P0002` 오류를 발생시킨다.

```sql
CREATE OR REPLACE FUNCTION proc_lab.fn_customer_order_summary_json(p_customer_id bigint)
RETURNS jsonb LANGUAGE plpgsql STABLE STRICT AS $function$
DECLARE
    v_customer proc_lab.customers%ROWTYPE;
    v_order_count integer;
    v_total_amount numeric;
BEGIN
    SELECT * INTO STRICT v_customer
      FROM proc_lab.customers WHERE customer_id = p_customer_id;
    SELECT count(*), coalesce(sum(total_amount), 0)
      INTO v_order_count, v_total_amount
      FROM proc_lab.orders
     WHERE customer_id = p_customer_id AND order_status <> 'CANCELLED';
    RETURN jsonb_build_object(
      'customer', jsonb_build_object('customer_id', v_customer.customer_id,
          'name', v_customer.customer_name, 'email', v_customer.email,
          'grade', v_customer.customer_grade),
      'order_count', v_order_count, 'total_amount', v_total_amount);
EXCEPTION WHEN NO_DATA_FOUND THEN
    RAISE EXCEPTION '고객번호 %를 찾을 수 없습니다.', p_customer_id
      USING ERRCODE = 'P0002';
END;
$function$;
```

원문 검증에서 고객 1번은 주문 2건, 총액 `305000.00`으로 출력됐고, 고객 999번은 `SQLSTATE: P0002`와 함께 오류가 발생했다. 조회 함수에서도 예외 계약을 명확히 해 호출자가 “데이터 없음”을 구분할 수 있게 한다.

## 4. 한 종류 상품 주문 생성 프로시저

`pr_create_order`는 수량 검증 → 활성 고객 확인 → 상품 행 `FOR UPDATE` 잠금 → 재고 검증 → 재고 차감 → 주문/주문상세 생성 순서로 실행한다. `FOR UPDATE`는 동시에 같은 재고를 읽어 과다 차감하는 경쟁 조건을 줄인다.

```sql
BEGIN;
CALL proc_lab.pr_create_order(1, 2, 3, NULL);
SELECT * FROM proc_lab.orders ORDER BY order_id DESC LIMIT 1;
SELECT * FROM proc_lab.order_items ORDER BY order_item_id DESC LIMIT 1;
SELECT product_id, product_name, stock_qty
FROM proc_lab.products WHERE product_id = 2;
ROLLBACK;
```

원문 기록에서는 새 주문번호 6, 주문 총액 `147000.00`, 상품 2의 수량 3개, 재고 147이 확인됐다. 마지막 `ROLLBACK`으로 실습 데이터 변경을 되돌렸다. 입력 수량은 1 이상이어야 하고, 비활성 고객·없는 상품·부족 재고에는 각기 예외 코드로 실패시킨다.

## 5. 주문 상태 전환과 이력

`pr_change_order_status`는 허용 상태(`PENDING`, `PAID`, `SHIPPING`, `COMPLETED`, `CANCELLED`)만 받고, 이전 상태와 다음 상태의 조합을 명시적으로 제한한다. 주문 행을 잠근 뒤 상태를 바꾸고 `order_status_history`에 이전·이후 값을 기록한다.

원문 검증은 `SHIPPING → COMPLETED` 전환 후 다음 메시지와 이력 행을 확인했다.

```plain text
주문 2: SHIPPING → COMPLETED 변경 완료
history_id|order_id|old_status|new_status|changed_by
----------+--------+----------+----------+----------
         1|       2|SHIPPING  |COMPLETED |postgres
```

상태 머신을 조건문으로 명시하면 “이미 완료된 주문을 다시 배송 처리” 같은 비즈니스 규칙 위반을 DB 경계에서 막을 수 있다.

## 6. 멱등 일괄 할인

`pr_bulk_discount_once`는 `batch_key`를 유일한 실행 식별자로 사용한다. 먼저 `bulk_discount_runs`에 `PROCESSING` 행을 삽입하고 `ON CONFLICT DO NOTHING`으로 최초 실행권을 확보한다. 이미 같은 키가 있으면 이전 조건·결과를 확인해 재실행에는 기존 처리 건수를 반환한다.

```sql
CALL proc_lab.pr_bulk_discount_once('DAY04-SALE-001', 10, 70000, NULL);
-- 원문: 처리건수=3
CALL proc_lab.pr_bulk_discount_once('DAY04-SALE-001', 10, 70000, NULL);
-- 원문: 이미 완료된 batch_key이며 기존 처리건수=3
```

첫 실행 후 89,000원 키보드는 80,100원, 329,000원 모니터는 296,100원, 79,000원 웹캠은 71,100원이 됐다. 두 번째 호출 뒤에도 가격은 변하지 않았다. 같은 `batch_key`를 다른 할인 조건과 함께 제출하면 오류로 막아, 키 충돌이 조용히 다른 작업을 재사용하는 일을 방지한다.

## 7. orders 감사 트리거

`fn_audit_orders()`는 `INSERT`·`UPDATE`·`DELETE` 뒤에 `audit_log`에 테이블명, 연산, 행 ID, 변경 전후 JSON, 세션 사용자를 기록한다. `SECURITY DEFINER`에는 다음처럼 안전한 검색 경로를 같이 둔다.

```sql
CREATE OR REPLACE FUNCTION proc_lab.fn_audit_orders()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER
SET search_path = pg_catalog, proc_lab, pg_temp
AS $function$
BEGIN
  INSERT INTO proc_lab.audit_log
    (table_name, operation, row_id, old_data, new_data, changed_by)
  VALUES (TG_TABLE_NAME, TG_OP,
    CASE WHEN TG_OP = 'DELETE' THEN OLD.order_id ELSE NEW.order_id END,
    CASE WHEN TG_OP IN ('UPDATE', 'DELETE') THEN to_jsonb(OLD) END,
    CASE WHEN TG_OP IN ('INSERT', 'UPDATE') THEN to_jsonb(NEW) END,
    session_user);
  IF TG_OP = 'DELETE' THEN RETURN OLD; END IF;
  RETURN NEW;
END;
$function$;
```

원문은 주문 1번 `note` 변경 후 `audit_log`의 `UPDATE`, 이전 JSON, 이후 JSON을 확인하고 롤백했다. 감사 트리거는 애플리케이션 경로와 관계없이 기록할 수 있지만, 민감 데이터가 로그 JSON에 포함되지 않도록 별도 정책이 필요하다.

## 8. 주문상세 변경에 따른 총액 동기화

`order_items`의 삽입·수정·삭제 뒤 `fn_sync_order_total()`이 해당 주문의 `sum(line_amount)`를 다시 계산해 `orders.total_amount`에 반영한다. 수정으로 주문 ID가 바뀐 경우에는 이전 주문과 새 주문 모두를 갱신한다.

원문 검증은 주문 3에 상세 행을 넣고 수량을 바꾸고 지우는 순서로 총액이 `118000.00 → 296000.00 → 385000.00 → 118000.00`으로 변하는 것을 확인했다. 이는 파생값을 애플리케이션에서 누적 계산하는 대신 DB 변경 이벤트에 묶어 일관성을 보장하는 예다. 다만 대량 변경에서는 행 단위 재집계 비용과 트리거 연쇄를 측정해야 한다.
