# [스프링 MVC 2편 - 백엔드 웹 개발 핵심 기술] 11. 파일 업로드

> 원문: https://ch010104.tistory.com/293

## 본문

1. 파일 업로드 소개 일반적으로 사용하는 HTML Form을 통한 파일 업로드를 이해하려면 먼저 폼을 전송하는 두 가지 방식(application/x-www-form-urlencoded, multipart/form-data)의 차이를 명확히 이해해야 합니다. 1) application/x-www-form-urlencoded 방식 HTML Form 데이터를 서버로 전송하는 가장 기본적인 방법입니다. Form 태그에 별도의 enctype 옵션이 없으면 웹 브라우저는 요청 HTTP 메시지의 헤더에 다음 내용을 자동으로 추가합니다.   Content-Type: application/x-www-form-urlencoded   전송 메커니즘: 폼에 입력한 필드 데이터를 HTTP Body에 문자로 username=kim&age=20과 같이 & 구분자를 연결하여 전송합니다. 한계점: 파일을 업로드하려면 문자가 아닌 바이너리 데이터를 전송해야 합니다. 이 방식은 문자를 전송하는 방식이므로 대용량 바이너리 파일을 전송하기에 적합하지 않습니다. 또한 보통 실무에서는 이름, 나이 같은 일반 문자 데이터와 파일(바이너리)을 동시에 전송해야 하는 상황이 많습니다. 문자와 바이너리를 동시 전송하기 위해 HTTP는 multipart/form-data 방식을 제공합니다.  2) multipart/form-data 방식 문자와 바이너리 데이터를 동시에 한 번에 전송할 수 있도록 고안된 방식입니다.   이 방식을 사용하려면 HTML Form 태그에 반드시 enctype="multipart/form-data" 속성을 지정해야 합니다. 웹 브라우저가 생성한 요청 HTTP 메시지 예시 POST /save HTTP/1.1 Host: localhost:8080 Content-Type: multipart/form-data; boundary=----XXX Content-Length: 10457 ------XXX Content-Disposition: form-data; name="username" kim ------XXX Content-Disposition: form-data; name="age" 20 ------XXX Content-Disposition: form-data; name="file1"; filename="intro.png" Content-Type: image/png 109238a900p3eqwokjasd09ou3oirjwoe9u34ouief... [바이너리 데이터] ------XXX--  메시지 구조 특징:  헤더의 Content-Type에 boundary(경계 구분선) 키가 자동 생성됩니다. (예: boundary=----XXX) HTTP 바디 내부는 이 boundary 값을 기준으로 각 전송 필드가 분할되어 담깁니다. 각 부분을 Part라고 부릅니다. 일반 폼 데이터 파트는 각 항목별로 문자가 전송되고, 파일 파트의 경우 파일 이름(filename)과 해당 파일의 Content-Type 헤더가 별도로 추가된 후 바이너리 데이터가 이어집니다. 메시지의 마지막 구분선 끝에는 -가 붙어 전송의 끝을 알립니다.    2. 프로젝트 기본 메인 인덱스 페이지 사용자 편의 및 실습 메뉴 이동을 위해 추가해 두는 정적 리소스 페이지입니다. resources/static/index.html <!DOCTYPE html> <html> <head> <meta charset="UTF-8"> <title>Title</title> </head> <body> <ul> <li>상품 관리 <ul> <li><a href="/servlet/v1/upload">서블릿 파일 업로드1</a></li> <li><a href="/servlet/v2/upload">서블릿 파일 업로드2</a></li> <li><a href="/spring/upload">스프링 파일 업로드</a></li> <li><a href="/items/new">상품 파일, 이미지 업로드</a></li> </ul> </li> </ul> </body> </html> 3. 서블릿과 파일 업로드 1 가장 로우 레벨인 서블릿(Servlet)이 제공하는 Part 기술을 통해 어떻게 멀티파트 데이터를 처리하는지 알아봅니다. 1) 컨트롤러 구현 (ServletUploadControllerV1) package hello.upload.controller; import lombok.extern.slf4j.Slf4j; import org.springframework.stereotype.Controller; import org.springframework.web.bind.annotation.GetMapping; import org.springframework.web.bind.annotation.PostMapping; import org.springframework.web.bind.annotation.RequestMapping; import javax.servlet.ServletException; import javax.servlet.http.HttpServletRequest; import javax.servlet.http.Part; import java.io.IOException; import java.util.Collection; @Slf4j @Controller @RequestMapping("/servlet/v1") public class ServletUploadControllerV1 { @GetMapping("/upload") public String newFile() { return "upload-form"; } @PostMapping("/upload") public String saveFileV1(HttpServletRequest request) throws ServletException, IOException { log.info("request={}", request); String itemName = request.getParameter("itemName"); log.info("itemName={}", itemName); // 멀티파트 요청 시 각각 분할되어 들어오는 Part들을 수집 Collection<Part> parts = request.getParts(); log.info("parts={}", parts); return "upload-form"; } }  request.getParts(): multipart/form-data 전송 방식에서 각각의 경계(boundary)로 구분되어 넘어온 부분 데이터들을 수집해서 확인할 수 있게 해줍니다.  2) 업로드 폼 뷰 (resources/templates/upload-form.html) <!DOCTYPE HTML> <html xmlns:th="http://www.thymeleaf.org"> <head> <meta charset="utf-8"> </head> <body> <div class="container"> <div class="py-5 text-center"> <h2>상품 등록 폼</h2> </div> <h4 class="mb-3">상품 입력</h4> <form th:action method="post" enctype="multipart/form-data"> <ul> <li>상품명 <input type="text" name="itemName"></li> <li>파일<input type="file" name="file" ></li> </ul> <input type="submit"/> </form> </div> <!-- /container --> </body> </html> 3) 로깅 설정 (application.properties) HTTP 요청 전송 데이터 및 바디 상세 정보 로그를 확인하기 위해 옵션을 추가합니다. logging.level.org.apache.coyote.http11=trace  주의 (스프링 부트 3.2 이상): 스프링 부트 3.2 버전부터는 debug 대신 반드시 trace를 사용해야 아파치 Coyote의 HTTP 요청 메시지 로그가 콘솔에 정상 출력됩니다.  4) 멀티파트 서블릿 옵션 및 제어법 (1) 업로드 사이즈 제한 설정 무제한 크기의 대용량 파일 업로드를 방지하기 위해 파일 업로드 사이즈를 제한할 수 있습니다. 설정 범위를 초과하면 MaxUploadSizeExceededException (또는 내부적으로 SizeLimitExceededException)이 발생합니다. spring.servlet.multipart.max-file-size=1MB spring.servlet.multipart.max-request-size=10MB  max-file-size: 단일 파일 업로드 시 가질 수 있는 최대 파일 사이즈 크기입니다. (기본값: 1MB) max-request-size: 멀티파트 요청 한 번에 전송할 수 있는 전체 파트 데이터 합의 최대 사이즈 크기입니다. (기본값: 10MB)  (2) 멀티파트 처리 기능 활성화 여부 제어 (spring.servlet.multipart.enabled)  spring.servlet.multipart.enabled=false (기능 끄기)  서블릿 컨테이너가 멀티파트 요청에 대해 아무런 가공 처리를 하지 않습니다. 결과적으로 HTTP 바디 분석을 건너뛰게 되므로 request.getParameter("itemName") 및 request.getParts()의 호출 결과가 모두 비어있거나 null을 반환합니다.   spring.servlet.multipart.enabled=true (기본값: true)  스프링 부트가 작동하면서 서블릿 컨테이너에 멀티파트 요청을 처리하도록 지정합니다. 옵션을 켜면 컨트롤러의 request 객체가 단순 RequestFacade에서 스프링이 가공한 StandardMultipartHttpServletRequest 타입으로 변환됩니다. 이에 따라 일반 파라미터 텍스트뿐만 아니라 파트(Part) 바이너리 데이터까지 추출 및 조작이 가능한 상태가 됩니다.     참고 (MultipartResolver의 역할):멀티파트 활성화 옵션이 켜져 있으면 스프링의 DispatcherServlet은 멀티파트 리졸버(MultipartResolver)를 실행합니다. 멀티파트 리졸버는 일반 HttpServletRequest를 받아 멀티파트 처리에 특화된 MultipartHttpServletRequest 인터페이스를 구현한 구체 클래스(StandardMultipartHttpServletRequest)로 변환하여 넘겨줍니다. 이를 통해 컨트롤러에서 가공 처리된 편리한 객체를 다룰 수 있습니다. 다만, 이후 설명할 스프링 제공의 MultipartFile이 압도적으로 쓰기 편리하므로 MultipartHttpServletRequest 자체를 실무에서 직접 주입받아 쓰는 일은 드뭅니다.  4. 서블릿과 파일 업로드 2 서블릿의 Part 인터페이스 기능을 확장하여 실제로 클라이언트가 전송한 파일을 지정한 서버의 물리 디렉토리에 저장하는 코드를 실습합니다. 1) 파일 물리 디렉토리 설정 및 주의사항 가장 먼저 실제 로컬 컴퓨터에 파일이 저장될 물리 디렉토리 경로를 설정하고, 직접 해당 폴더를 생성해야 합니다. resources/main/application.properties file.dir=파일 업로드 경로 설정 (예: /Users/study/file/ 또는 C:/study/file/)  필독 주의사항:  운영체제에 알맞은 실제 물리 경로 폴더를 미리 하드디스크에 만들어 두어야 합니다. (미생성 시 입출력 예외 발생) application.properties 설정 파일에 기입할 때 경로의 마지막에 **/ (슬래시)**가 누락되지 않도록 주의해야 합니다.   2) 파일 저장용 컨트롤러 (ServletUploadControllerV2) package hello.upload.controller; import lombok.extern.slf4j.Slf4j; import org.springframework.beans.factory.annotation.Value; import org.springframework.stereotype.Controller; import org.springframework.util.StreamUtils; import org.springframework.util.StringUtils; import org.springframework.web.bind.annotation.GetMapping; import org.springframework.web.bind.annotation.PostMapping; import org.springframework.web.bind.annotation.RequestMapping; import javax.servlet.ServletException; import javax.servlet.http.HttpServletRequest; import javax.servlet.http.Part; import java.io.IOException; import java.io.InputStream; import java.nio.charset.StandardCharsets; import java.util.Collection; @Slf4j @Controller @RequestMapping("/servlet/v2") public class ServletUploadControllerV2 { // application.properties에 설정된 물리 디렉토리 경로 주입 @Value("${file.dir}") private String fileDir; @GetMapping("/upload") public String newFile() { return "upload-form"; } @PostMapping("/upload") public String saveFileV1(HttpServletRequest request) throws ServletException, IOException { log.info("request={}", request); String itemName = request.getParameter("itemName"); log.info("itemName={}", itemName); Collection<Part> parts = request.getParts(); log.info("parts={}", parts); for (Part part : parts) { log.info("==== PART ===="); log.info("name={}", part.getName()); // Part 자체의 헤더 목록 출력 Collection<String> headerNames = part.getHeaderNames(); for (String headerName : headerNames) { log.info("header {}: {}", headerName, part.getHeader(headerName)); } // 편의 메서드 제공 // 클라이언트가 업로드한 실제 파일명 조회 log.info("submittedFileName={}", part.getSubmittedFileName()); // Part Body의 데이터 크기 조회 log.info("size={}", part.getSize()); // 텍스트 데이터를 문자셋 변환하여 로깅 (단순 확인용) InputStream inputStream = part.getInputStream(); String body = StreamUtils.copyToString(inputStream, StandardCharsets.UTF_8); log.info("body={}", body); // 실제 파일 데이터가 들어있다면 물리 파일로 디렉토리에 저장 if (StringUtils.hasText(part.getSubmittedFileName())) { String fullPath = fileDir + part.getSubmittedFileName(); log.info("파일 저장 fullPath={}", fullPath); // 지정된 전체 경로(디렉토리 + 파일명)로 바이너리를 파일 시스템에 직접 작성 part.write(fullPath); } } return "upload-form"; } } 3) 서블릿 Part의 주요 메서드 기능 정리  part.getSubmittedFileName(): 클라이언트가 전송한 원래의 파일명(Original File Name)을 직접 얻어옵니다. part.getInputStream(): 해당 Part가 보관하는 전송 바이너리 데이터를 직접 바이트 스트림 형태로 읽어옵니다. part.write(String filepath): 파일의 최종 전체 경로를 매개변수로 받아 해당 스트림 바이너리 데이터를 디스크 파일로 즉시 저장합니다.   실습 시 로깅 팁:대용량 파일 전송 테스트를 진행할 경우 콘솔창에 엄청난 양의 바이너리 바이트 문자열 및 아파치 Coyote HTTP 바디 로그가 무한히 찍히게 되어 시스템이 느려지거나 오류가 날 수 있습니다. 정상 동작이 확인되면 아래의 두 로깅 처리를 주석하거나 꺼두는 것이 좋습니다.  logging.level.org.apache.coyote.http11=trace 설정 끄기 컨트롤러 내부의 스트림 보디 로깅 log.info("body={}", body); 제거하기   5. 스프링과 파일 업로드 서블릿 Part를 직접 제어하는 것은 다소 코드가 복잡하고 HttpServletRequest를 다루어야 해 번거롭습니다. 스프링은 이를 극도로 단순화해주는 최고의 도구인 MultipartFile 인터페이스를 제공합니다. 1) 컨트롤러 구현 (SpringUploadController) package hello.upload.controller; import lombok.extern.slf4j.Slf4j; import org.springframework.beans.factory.annotation.Value; import org.springframework.stereotype.Controller; import org.springframework.web.bind.annotation.GetMapping; import org.springframework.web.bind.annotation.PostMapping; import org.springframework.web.bind.annotation.RequestMapping; import org.springframework.web.bind.annotation.RequestParam; import org.springframework.web.multipart.MultipartFile; import javax.servlet.http.HttpServletRequest; import java.io.File; import java.io.IOException; @Slf4j @Controller @RequestMapping("/spring") public class SpringUploadController { @Value("${file.dir}") private String fileDir; @GetMapping("/upload") public String newFile() { return "upload-form"; } @PostMapping("/upload") public String saveFile(@RequestParam String itemName, @RequestParam MultipartFile file, HttpServletRequest request) throws IOException { log.info("request={}", request); log.info("itemName={}", itemName); log.info("multipartFile={}", file); if (!file.isEmpty()) { // 업로드한 파일에서 원본 파일명 획득 후 경로 결합 String fullPath = fileDir + file.getOriginalFilename(); log.info("파일 저장 fullPath={}", fullPath); // 스프링이 제공하는 편리한 저장 메서드를 활용하여 디렉토리에 파일 작성 file.transferTo(new File(fullPath)); } return "upload-form"; } } 2) 스프링 파일 업로드 핵심 분석  @RequestParam MultipartFile file / @ModelAttribute 사용 가능:  HTML Form 내 파일 선택 <input type="file" name="file">의 name 값과 매핑되도록 컨트롤러 파라미터 이름을 지정하면 별도의 추출 작업 없이 바로 스프링이 파싱하여 주입해 줍니다.   MultipartFile의 핵심 메서드 API:  file.isEmpty(): 업로드 파일이 비어있는지 여부를 체크합니다.
