## 학습 목표 및 맥락

SQL을 직접 사용하는 경우 스프링이 제공하는 JdbcTemplate은 좋은 선택지다. JDBC를 편리하게 사용하도록 돕고, 템플릿 콜백 패턴으로 반복 작업을 처리한다.

순수 JDBC에서는 리포지토리 메서드마다 커넥션 획득 → PreparedStatement 생성 → 파라미터 바인딩 → SQL 실행 → 결과 순회 → 리소스 종료 → SQLException 변환을 반복해야 한다. JdbcTemplate은 이 반복 흐름을 맡기고, 개발자가 SQL·파라미터·결과 매핑에 집중하게 한다.

## 원문 기반 학습 정리

### 1. JdbcTemplate 소개와 설정

SQL을 직접 사용하는 경우 스프링이 제공하는 JdbcTemplate은 좋은 선택지다. JDBC를 편리하게 사용하도록 돕고, 템플릿 콜백 패턴으로 반복 작업을 처리한다.

순수 JDBC에서는 리포지토리 메서드마다 커넥션 획득 → PreparedStatement 생성 → 파라미터 바인딩 → SQL 실행 → 결과 순회 → 리소스 종료 → SQLException 변환을 반복해야 한다. JdbcTemplate은 이 반복 흐름을 맡기고, 개발자가 SQL·파라미터·결과 매핑에 집중하게 한다.

JdbcTemplate은 ORM이 아니다. SQL의 작성과 결과 의미는 리포지토리가 책임지고, JDBC의 자원 관리와 실행 절차만 템플릿이 담당한다. 리포지토리에 Connection이 아닌 DataSource를 주입하는 이유도 여기에 있다. 스프링 트랜잭션이 시작된 경우 템플릿은 현재 트랜잭션에 연결된 커넥션을 사용하므로, 서비스 계층의 여러 DB 작업을 같은 트랜잭션 문맥에서 수행할 수 있다.

### 2. JdbcTemplate 적용 1 - 기본

ItemRepository 인터페이스를 기반으로 JdbcTemplate 구현체를 추가한다.

### JdbcTemplateItemRepositoryV1

```java
package hello.itemservice.repository.jdbctemplate;

import hello.itemservice.domain.Item;
import hello.itemservice.repository.ItemRepository;
import hello.itemservice.repository.ItemSearchCond;
import hello.itemservice.repository.ItemUpdateDto;
import lombok.extern.slf4j.Slf4j;
import org.springframework.dao.EmptyResultDataAccessException;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.core.RowMapper;
import org.springframework.jdbc.support.GeneratedKeyHolder;
import org.springframework.jdbc.support.KeyHolder;
import org.springframework.stereotype.Repository;
import org.springframework.util.StringUtils;

import javax.sql.DataSource;
import java.sql.PreparedStatement;
import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

/**
 * JdbcTemplate
 */
@Slf4j
@Repository
public class JdbcTemplateItemRepositoryV1 implements ItemRepository {

    private final JdbcTemplate template;

    public JdbcTemplateItemRepositoryV1(DataSource dataSource) {
        this.template = new JdbcTemplate(dataSource);
    }

    @Override
    public Item save(Item item) {
        String sql = "insert into item (item_name, price, quantity) values (?, ?, ?)";
        KeyHolder keyHolder = new GeneratedKeyHolder();

        template.update(connection -> {
            //자동 증가 키
            PreparedStatement ps = connection.prepareStatement(sql, new String[]{"id"});
            ps.setString(1, item.getItemName());
            ps.setInt(2, item.getPrice());
            ps.setInt(3, item.getQuantity());
            return ps;
        }, keyHolder);

        long key = keyHolder.getKey().longValue();
        item.setId(key);
        return item;
    }

    @Override
    public void update(Long itemId, ItemUpdateDto updateParam) {
        String sql = "update item set item_name=?, price=?, quantity=? where id=?";

        template.update(sql,
                updateParam.getItemName(),
                updateParam.getPrice(),
                updateParam.getQuantity(),
                itemId);
    }

    @Override
    public Optional<Item> findById(Long id) {
        String sql = "select id, item_name, price, quantity from item where id = ?";

        try {
            Item item = template.queryForObject(sql, itemRowMapper(), id);
            return Optional.of(item);
        } catch (EmptyResultDataAccessException e) {
            return Optional.empty();
        }
    }

    @Override
    public List<Item> findAll(ItemSearchCond cond) {
        String itemName = cond.getItemName();
        Integer maxPrice = cond.getMaxPrice();

        String sql = "select id, item_name, price, quantity from item";

        //동적 쿼리
        if (StringUtils.hasText(itemName) || maxPrice != null) {
            sql += " where";
        }

        boolean andFlag = false;
        List<Object> param = new ArrayList<>();

        if (StringUtils.hasText(itemName)) {
            sql += " item_name like concat('%',?,'%')";
            param.add(itemName);
            andFlag = true;
        }

        if (maxPrice != null) {
            if (andFlag) {
                sql += " and";
            }
            sql += " price <= ?";
            param.add(maxPrice);
        }

        log.info("sql={}", sql);
        return template.query(sql, itemRowMapper(), param.toArray());
    }

    private RowMapper<Item> itemRowMapper() {
        return (rs, rowNum) -> {
            Item item = new Item();
            item.setId(rs.getLong("id"));
            item.setItemName(rs.getString("item_name"));
            item.setPrice(rs.getInt("price"));
            item.setQuantity(rs.getInt("quantity"));
            return item;
        };
    }
}
```

### 핵심 메서드와 코드 흐름

JdbcTemplateItemRepositoryV1은 인터페이스는 그대로 두고 구현 기술만 JDBC 직접 사용에서 JdbcTemplate으로 교체한 코드다. 따라서 서비스와 컨트롤러는 변경하지 않는다.

this.template = new JdbcTemplate(dataSource): 생성자에서 DataSource를 주입받아 템플릿을 만든다. 템플릿이 커넥션 획득·반환을 담당한다.

template.update(): INSERT, UPDATE, DELETE에 사용하며 영향받은 행 수를 int로 반환한다. 0이면 대상 데이터가 없거나 조건이 맞지 않았을 수 있으므로, 실제 처리 정책은 도메인 요구사항으로 결정한다.

KeyHolder와 connection.prepareStatement(sql, new String[]{"id"}): identity 방식에서 DB가 생성한 id를 INSERT 뒤에 받아 item.setId(key)로 엔티티 상태를 완성한다.

template.queryForObject(): 결과가 정확히 하나일 때 사용한다. 결과가 없으면 EmptyResultDataAccessException, 둘 이상이면 IncorrectResultSizeDataAccessException이 발생한다. 이 강의의 findById()는 이 예외를 Optional.empty()로 바꿔 리포지토리 인터페이스의 계약을 유지한다.

template.query(): 결과가 하나 이상일 때 사용하며, 결과가 없으면 빈 컬렉션을 반환한다.

RowMapper는 ResultSet 전체가 아니라 한 행을 Item으로 바꾸는 책임만 가진다. ResultSet 반복은 JdbcTemplate이 처리한다.

```text
<T> T queryForObject(String sql, RowMapper<T> rowMapper, Object... args) throws DataAccessException;
```

```text
<T> List<T> query(String sql, RowMapper<T> rowMapper, Object... args) throws DataAccessException;
```

### itemRowMapper()가 동작하는 방식

```text
while(resultSet 이 끝날 때 까지) {
  rowMapper(rs, rowNum)
}
```

JdbcTemplate이 반복 루프를 처리하고, 개발자는 RowMapper 내부에서 ResultSet 한 행을 객체로 변환하는 코드만 작성한다.

### 3. JdbcTemplate 적용 2 - 동적 쿼리 문제

findAll()은 검색 조건에 따라 SQL을 다르게 만들어야 한다.

### 검색 조건 없음

```sql
select id, item_name, price, quantity from item
```

### 상품명(itemName) 검색

```sql
select id, item_name, price, quantity from item
 where item_name like concat('%',?,'%')
```

### 최대 가격(maxPrice) 검색

```sql
select id, item_name, price, quantity from item
 where price <= ?
```

### 상품명과 최대 가격을 모두 검색

```sql
select id, item_name, price, quantity from item
 where item_name like concat('%',?,'%')
   and price <= ?
```

where, and, 파라미터 순서 등을 조건별로 계산해야 하므로 동적 쿼리는 복잡해진다. V1에서는 SQL 조건을 추가한 순서와 param.add(...) 순서가 반드시 같아야 한다.

andFlag는 앞 조건이 이미 추가됐는지를 기억해 and 삽입 여부를 결정한다. 이름 지정 파라미터로 바꾸면 값과 SQL 자리를 이름으로 연결해 순서 버그는 줄일 수 있지만, 어떤 조건을 붙일지와 where·and를 어떻게 조립할지는 여전히 직접 해결해야 한다. 실무에서 조건·정렬·페이징 분기가 계속 늘어나면 다음 강의의 MyBatis가 필요한 이유가 된다.

### 5. 이름 지정 파라미터 1 - 순서 기반 바인딩의 위험

기본 JdbcTemplate은 ? 위치에 파라미터를 순서대로 바인딩한다.

```text
String sql = "update item set item_name=?, price=?, quantity=? where id=?";

template.update(sql,
        itemName,
        price,
        quantity,
        itemId);
```

다음처럼 SQL의 price, quantity 순서만 바꾸고 파라미터 순서를 놓치면 데이터가 잘못 저장된다.

```text
String sql = "update item set item_name=?, quantity=?, price=? where id=?";

template.update(sql,
        itemName,
        price,
        quantity,
        itemId);
```

이 경우 결과는 다음과 같다.

```text
item_name=itemName, quantity=price, price=quantity
```

데이터베이스에 잘못 저장된 데이터는 코드 수정만으로 끝나지 않고 데이터 복구까지 필요하므로 특히 위험하다. 이를 보완하기 위해 NamedParameterJdbcTemplate을 사용한다.

### 6. 이름 지정 파라미터 2 - NamedParameterJdbcTemplate

### JdbcTemplateItemRepositoryV2

```java
package hello.itemservice.repository.jdbctemplate;

import hello.itemservice.domain.Item;
import hello.itemservice.repository.ItemRepository;
import hello.itemservice.repository.ItemSearchCond;
import hello.itemservice.repository.ItemUpdateDto;
import lombok.extern.slf4j.Slf4j;
import org.springframework.dao.EmptyResultDataAccessException;
import org.springframework.jdbc.core.BeanPropertyRowMapper;
import org.springframework.jdbc.core.RowMapper;
import org.springframework.jdbc.core.namedparam.BeanPropertySqlParameterSource;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;
import org.springframework.jdbc.core.namedparam.NamedParameterJdbcTemplate;
import org.springframework.jdbc.core.namedparam.SqlParameterSource;
import org.springframework.jdbc.support.GeneratedKeyHolder;
import org.springframework.jdbc.support.KeyHolder;
import org.springframework.stereotype.Repository;
import org.springframework.util.StringUtils;

import javax.sql.DataSource;
import java.util.List;
import java.util.Map;
import java.util.Optional;

/**
 * NamedParameterJdbcTemplate
 * SqlParameterSource
 * - BeanPropertySqlParameterSource
 * - MapSqlParameterSource
 * Map
 *
 * BeanPropertyRowMapper
 *
 */
@Slf4j
@Repository
public class JdbcTemplateItemRepositoryV2 implements ItemRepository {

    private final NamedParameterJdbcTemplate template;

    public JdbcTemplateItemRepositoryV2(DataSource dataSource) {
        this.template = new NamedParameterJdbcTemplate(dataSource);
    }

    @Override
    public Item save(Item item) {
        String sql = "insert into item (item_name, price, quantity) " +
                     "values (:itemName, :price, :quantity)";

        SqlParameterSource param = new BeanPropertySqlParameterSource(item);
        KeyHolder keyHolder = new GeneratedKeyHolder();
        template.update(sql, param, keyHolder);

        Long key = keyHolder.getKey().longValue();
        item.setId(key);
        return item;
    }

    @Override
    public void update(Long itemId, ItemUpdateDto updateParam) {
        String sql = "update item " +
                "set item_name=:itemName, price=:price, quantity=:quantity " +
                "where id=:id";

        SqlParameterSource param = new MapSqlParameterSource()
                .addValue("itemName", updateParam.getItemName())
                .addValue("price", updateParam.getPrice())
                .addValue("quantity", updateParam.getQuantity())
                .addValue("id", itemId); //이 부분이 별도로 필요하다.

        template.update(sql, param);
    }

    @Override
    public Optional<Item> findById(Long id) {
        String sql = "select id, item_name, price, quantity from item where id = :id";

        try {
            Map<String, Object> param = Map.of("id", id);
            Item item = template.queryForObject(sql, param, itemRowMapper());
            return Optional.of(item);
        } catch (EmptyResultDataAccessException e) {
            return Optional.empty();
        }
    }

    @Override
    public List<Item> findAll(ItemSearchCond cond) {
        Integer maxPrice = cond.getMaxPrice();
        String itemName = cond.getItemName();
        SqlParameterSource param = new BeanPropertySqlParameterSource(cond);

        String sql = "select id, item_name, price, quantity from item";

        //동적 쿼리
        if (StringUtils.hasText(itemName) || maxPrice != null) {
            sql += " where";
        }

        boolean andFlag = false;

        if (StringUtils.hasText(itemName)) {
            sql += " item_name like concat('%',:itemName,'%')";
            andFlag = true;
        }

        if (maxPrice != null) {
            if (andFlag) {
                sql += " and";
            }
            sql += " price <= :maxPrice";
        }

        log.info("sql={}", sql);
        return template.query(sql, param, itemRowMapper());
    }

    private RowMapper<Item> itemRowMapper() {
        return BeanPropertyRowMapper.newInstance(Item.class); //camel 변환 지원
    }
}
```

### 이름 지정 바인딩

? 대신 :파라미터이름을 사용한다. V1처럼 SQL의 price, quantity 순서만 바꾸고 인수 순서를 놓쳐 데이터를 잘못 저장하는 문제를 줄인다. 다만 이름 지정 파라미터는 동적 SQL 자체를 만들지 않는다. where 조건의 존재 여부, and·or 결합, 정렬·페이징 구조는 여전히 개발자가 책임진다.

```sql
insert into item (item_name, price, quantity) " +
             "values (:itemName, :price, :quantity)"
```

NamedParameterJdbcTemplate은 DB가 생성한 키도 편리하게 조회한다.

### 전달할 파라미터 종류

### 1. Map

```text
Map<String, Object> param = Map.of("id", id);
Item item = template.queryForObject(sql, param, itemRowMapper());
```

### 2. MapSqlParameterSource

Map과 유사하지만 SQL 타입 지정 등 SQL 특화 기능을 제공한다. SqlParameterSource의 구현체이며 메서드 체인을 지원한다.

```text
SqlParameterSource param = new MapSqlParameterSource()
        .addValue("itemName", updateParam.getItemName())
        .addValue("price", updateParam.getPrice())
        .addValue("quantity", updateParam.getQuantity())
        .addValue("id", itemId); //이 부분이 별도로 필요하다.

template.update(sql, param);
```

### 3. BeanPropertySqlParameterSource

자바빈 프로퍼티 규약으로 파라미터 객체를 자동 생성한다.

```text
getXxx() -> xxx
getItemName() -> itemName
```

```text
SqlParameterSource param = new BeanPropertySqlParameterSource(item);
KeyHolder keyHolder = new GeneratedKeyHolder();
template.update(sql, param, keyHolder);
```

BeanPropertySqlParameterSource는 편리하지만, SQL의 :id처럼 DTO에 없는 값이 필요하면 사용할 수 없다. update()의 ItemUpdateDto에는 itemId가 없으므로 그 경우 MapSqlParameterSource를 사용한다.

이름 기반 바인딩도 SQL의 :itemName과 getItemName()처럼 이름이 일치해야 한다.

### BeanPropertyRowMapper

V1의 매핑 코드는 다음과 같다.

```text
private RowMapper<Item> itemRowMapper() {
    return (rs, rowNum) -> {
        Item item = new Item();
        item.setId(rs.getLong("id"));
        item.setItemName(rs.getString("item_name"));
        item.setPrice(rs.getInt("price"));
        item.setQuantity(rs.getInt("quantity"));
        return item;
    };
}
```

V2는 BeanPropertyRowMapper로 대체한다.

```text
private RowMapper<Item> itemRowMapper() {
    return BeanPropertyRowMapper.newInstance(Item.class); //camel 변환 지원
}
```

BeanPropertyRowMapper는 조회 결과를 자바빈 규약에 맞춰 변환한다. 일반적인 snake_case ↔ camelCase 변환을 지원하므로 item_name은 itemName으로 매핑된다. DB 컬럼과 객체 속성의 의미 자체가 다르면 자동 추론에 맡기지 말고 SQL 별칭을 명시한다.

```sql
select member_name as username
```

단순 CRUD는 BeanPropertyRowMapper로 중복을 줄이고, 계산값·복잡한 조인·값 변환이 많을 때는 어떤 컬럼을 어떤 필드에 넣는지 드러나는 명시적 RowMapper를 사용하는 편이 안전하다.

```text
Item item = new Item();
item.setId(rs.getLong("id"));
item.setPrice(rs.getInt("price"));
```

snake_case의 item_name은 camelCase의 itemName으로 자동 변환한다.

DB 컬럼명과 객체 속성명이 완전히 다르면 SQL 별칭을 사용한다.

```sql
select item_name as itemName
```

```sql
select member_name as username
```

### 8. SimpleJdbcInsert

JdbcTemplate은 INSERT SQL을 직접 작성하지 않도록 SimpleJdbcInsert를 제공한다.

### JdbcTemplateItemRepositoryV3

```java
package hello.itemservice.repository.jdbctemplate;

import hello.itemservice.domain.Item;
import hello.itemservice.repository.ItemRepository;
import hello.itemservice.repository.ItemSearchCond;
import hello.itemservice.repository.ItemUpdateDto;
import lombok.extern.slf4j.Slf4j;
import org.springframework.dao.EmptyResultDataAccessException;
import org.springframework.jdbc.core.BeanPropertyRowMapper;
import org.springframework.jdbc.core.RowMapper;
import org.springframework.jdbc.core.namedparam.BeanPropertySqlParameterSource;
import org.springframework.jdbc.core.namedparam.MapSqlParameterSource;
import org.springframework.jdbc.core.namedparam.NamedParameterJdbcTemplate;
import org.springframework.jdbc.core.namedparam.SqlParameterSource;
import org.springframework.jdbc.core.simple.SimpleJdbcInsert;
import org.springframework.stereotype.Repository;
import org.springframework.util.StringUtils;

import javax.sql.DataSource;
import java.util.List;
import java.util.Map;
import java.util.Optional;

/**
 * SimpleJdbcInsert
 */
@Slf4j
@Repository
public class JdbcTemplateItemRepositoryV3 implements ItemRepository {

    private final NamedParameterJdbcTemplate template;
    private final SimpleJdbcInsert jdbcInsert;

    public JdbcTemplateItemRepositoryV3(DataSource dataSource) {
        this.template = new NamedParameterJdbcTemplate(dataSource);
        this.jdbcInsert = new SimpleJdbcInsert(dataSource)
                .withTableName("item")
                .usingGeneratedKeyColumns("id");
//                .usingColumns("item_name", "price", "quantity"); //생략 가능
    }

    @Override
    public Item save(Item item) {
        SqlParameterSource param = new BeanPropertySqlParameterSource(item);
        Number key = jdbcInsert.executeAndReturnKey(param);
        item.setId(key.longValue());
        return item;
    }

    @Override
    public void update(Long itemId, ItemUpdateDto updateParam) {
        String sql = "update item " +
                "set item_name=:itemName, price=:price, quantity=:quantity " +
                "where id=:id";

        SqlParameterSource param = new MapSqlParameterSource()
                .addValue("itemName", updateParam.getItemName())
                .addValue("price", updateParam.getPrice())
                .addValue("quantity", updateParam.getQuantity())
                .addValue("id", itemId);

        template.update(sql, param);
    }

    @Override
    public Optional<Item> findById(Long id) {
        String sql = "select id, item_name, price, quantity from item where id = :id";

        try {
            Map<String, Object> param = Map.of("id", id);
            Item item = template.queryForObject(sql, param, itemRowMapper());
            return Optional.of(item);
        } catch (EmptyResultDataAccessException e) {
            return Optional.empty();
        }
    }

    @Override
    public List<Item> findAll(ItemSearchCond cond) {
        Integer maxPrice = cond.getMaxPrice();
        String itemName = cond.getItemName();
        SqlParameterSource param = new BeanPropertySqlParameterSource(cond);

        String sql = "select id, item_name, price, quantity from item";

        //동적 쿼리
        if (StringUtils.hasText(itemName) || maxPrice != null) {
            sql += " where";
        }

        boolean andFlag = false;

        if (StringUtils.hasText(itemName)) {
            sql += " item_name like concat('%',:itemName,'%')";
            andFlag = true;
        }

        if (maxPrice != null) {
            if (andFlag) {
                sql += " and";
            }
            sql += " price <= :maxPrice";
        }

        log.info("sql={}", sql);
        return template.query(sql, param, itemRowMapper());
    }

    private RowMapper<Item> itemRowMapper() {
        return BeanPropertyRowMapper.newInstance(Item.class);
    }
}
```

### SimpleJdbcInsert 설정

```text
this.jdbcInsert = new SimpleJdbcInsert(dataSource)
                .withTableName("item")
                .usingGeneratedKeyColumns("id");
//                .usingColumns("item_name", "price", "quantity"); //생략 가능
```

withTableName: 데이터를 저장할 테이블명을 지정한다.

usingGeneratedKeyColumns: 생성되는 PK 컬럼명을 지정한다.

usingColumns: INSERT에 사용할 컬럼을 지정한다. 특정 컬럼만 저장할 때 쓰며 생략 가능하다.

SimpleJdbcInsert는 생성 시점에 테이블 메타데이터를 조회하므로 usingColumns를 생략할 수 있다. 실행 시 다음 INSERT SQL을 생성한 것을 로그에서 확인할 수 있다.

```sql
DEBUG 39424 --- [           main] o.s.jdbc.core.simple.SimpleJdbcInsert    :
Compiled insert object: insert string is [INSERT INTO item (ITEM_NAME, PRICE,
QUANTITY) VALUES(?, ?, ?)]
```
