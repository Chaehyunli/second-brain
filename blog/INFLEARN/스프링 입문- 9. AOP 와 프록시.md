# [스프링 입문] 9. AOP 와 프록시

## 원문

https://ch010104.tistory.com/212

## 핵심 요약

- **1. AOP가 필요한 상황 (Before AOP)** — 기존의 MemberService는 아래와 같이 핵심 로직보다 시간 측정 로직이 더 비대해진 상태였습니다.
- **2. AOP 적용 후: 코드의 분리** — 이제 TimeTraceAop를 통해 시간 측정 로직을 완전히 밖으로 빼냅니다.
- **① 가짜 객체(Proxy)의 생성** — 스프링 컨테이너가 올라갈 때, AOP 설정(@Aspect)을 보고 MemberService를 복제한 **가짜 객체(Proxy)**를 만듭니다.
- **② 의존관계 주입(DI)의 역할** — MemberController는 MemberService를 주입받을 때, 스프링이 가짜(Proxy)를 넣어줘도 아무 의심 없이 받습니다.
